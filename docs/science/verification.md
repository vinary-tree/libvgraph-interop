# Verification and falsification method

The implementation was specified and model-checked before production Rust was written. This
document records the hypotheses, independent methods, causal mutants, and executable refinements.
Formal-tool names and shared notation are defined in the [glossary](../glossary.md).

## Hypotheses

The campaign tests these falsifiable claims:

1. Exact encoding followed by exact decoding preserves every canonical graph.
2. Equivalent raw edge enumerations produce one byte representation.
3. Unknown schemas, versions, flags, profiles, malformed lengths, noncanonical CSR, stale digests,
   exhausted work, and cancellation never publish a graph.
4. Work and heap usage are linear in vertices plus edges.
5. Native call depth is independent of graph depth.
6. Concurrent independent requests cannot change results.
7. A release cannot publish unless every command used by its portable gates belongs to the
   explicitly checked tool closure.
8. A release cannot publish unless the fetched formal checkout equals the canonical production
   proof binding.

## Exhaustive corpus

The independent model and production suite enumerate all 531 directed graphs through three
vertices. Across three profiles they check 1,593 encodings, 9,321 lawful renamings, and 180,696
strict-prefix rejections. Two literal golden vectors prevent encoder and decoder from drifting
together.

## Property tests

Generated tests vary vertex counts, duplicate-heavy edge enumerations, reverse insertion orders,
profiles, and bijective dense renaming. Assertions cover round trips, canonical byte uniqueness,
profile isolation, digest separation, preservation of renamed edges, the closed-form work bound,
and every unsupported `u16` major/minor version pair generated by the property engine. This method
follows Claessen and Hughes' original QuickCheck formulation of executable universal properties
([paper](https://doi.org/10.1145/351240.351266)).

## Malformed and mutation tests

The deterministic malformed matrix mutates every header class, representative exact-version
alternatives,
payload declarations, truncation and trailing bytes, offset origin/order/terminal, target range,
row duplication/order, resource limits, work admission, cancellation, and stale digests. The fuzz
target applies bounded decoding to arbitrary bytes. Mutation testing is run against the production
wire and digest modules; survivors are defects unless a documented equivalent mutant is proven.
The method and its limitations are interpreted using Papadakis et al.'s mutation-testing survey
([paper](https://doi.org/10.1016/bs.adcom.2018.03.015)). Release evidence is accepted only when the
fuzz and mutation runners record the exact clean source commit, pinned tool versions, lockfile
hashes, complete outcomes, and no crash, missed, or timeout artifact.

## Stack and concurrency tests

A complete build, encode, decode, comparison, unwind, and drop lifecycle for 100,000 vertices runs
on a 64 KiB thread stack. Eight simultaneous readers decode one shared immutable byte slice and
must produce the same canonical edges without shared mutable codec state.

## Acceptance order

The portable gate first requires a clean source commit, then executes formal provenance,
refinement, tool provisioning, ShellCheck, strict YAML lint, root and fuzz formatting, Cargo check,
strict Clippy, tests, doctests, rustdoc, dependency policy, release-workflow policy and causal
mutants, workflow lint, documentation rendering and lint, package inventory, package construction,
and a final clean-source check—in that order.
The complete local gate then runs commit-bound fuzzing, mutation testing, benchmarking, and pgmcp's
bug gate. Every validation command writes complete output below repository-backed
`target/verification`; no verifier uses memory-backed `/tmp` storage.

## Resource and stack evidence

The formal returned-graph storage count is exactly $`2V + 1 + E`$ initialized `u32`-sized words:
$`V`$ dense nodes, $`V + 1`$ offsets, and $`E`$ targets. Allocator capacity may be larger. The
conservative complete-decode logical charge is:

```math
W(V,E) = 10 + 4V + 3E.
```

The executable model validates both equations at their boundaries. Production property tests
validate the work expression over generated `u32` counts. The 64 KiB stack test performs full graph
comparison, rejects a target corrupted after buffer materialization, drops that error path, and
forces unwinding while owning a 100,000-vertex decoded graph. Together with the explicit-loop source
structure, this is the production refinement of the formal native-depth invariant.

## Evidence binding

`formal/refinement.tsv` contains all 76 ordered formal-to-production mappings. The refinement gate
exactly projects the frozen ledger, resolves every formal symbol in the signed commit, and resolves
every production symbol in the candidate. Release acceptance additionally requires all production
evidence to name the same clean candidate commit. The release evidence bundle and its SHA-256
manifest are attached before an immutable GitHub release is published, so short-lived workflow
artifacts are diagnostic copies rather than the permanent record.
